# CVM++: Stack-Based Virtual Machine and Bytecode Compiler

CVM++ is a custom interpreter, bytecode compiler, and virtual machine written entirely in modern C++ from scratch. It features an on-demand lexical scanner, a recursive descent parser that builds an Abstract Syntax Tree (AST), and a compiler that flattens the tree into raw bytecode operations executed on a zero-address stack architecture.

## Performance & Safety Architecture

The CVM is engineered for maximum performance while maintaining strict runtime safety bounds. It achieves **>440M ops/sec** with **~2.2ns latency per opcode**:

- **Direct Threading (Computed Gotos):** Replaces the standard VM switch-dispatch loop with an array of memory addresses, eliminating dispatch branch mispredictions and drastically improving pipeline throughput.
- **C++20 Branch Predictor Hints (`[[likely]]`/`[[unlikely]]`):** VM stack bounds and division-by-zero checks are evaluated without stalling the CPU pipeline.
- **C++17 `std::string_view`:** The on-demand lexical scanner extracts tokens from the source code with zero heap allocations.
- **Memory Safe:** Strict runtime checks prevent stack overflows, stack underflows, and division by zero. Compile-time passes enforce a maximum variable limit (256) and prevent the usage of uninitialized variables.
- **RAII and Smart Pointers:** Uses C++ Standard Containers (`std::array`, `std::vector`) and `std::shared_ptr` to guarantee 100% automatic memory deallocation without leaks, even when user scripts trigger fatal exceptions.

## Architecture Pipeline

1. **Lexical Analysis (Scanner):** An on-demand tokenizer that reads raw source code character-by-character and groups them into meaningful `Token` structures.
2. **Recursive Descent Parser:** Processes tokens based on strict operator precedence (BODMAS/PEMDAS) and language grammar to build an AST.
3. **Bytecode Compiler:** Traverses the AST to generate a flat, dense array of raw integer Operation Codes (Opcodes). It automatically handles jump patching for loops and conditional branching.
4. **Virtual Machine (VM):** A simulated CPU execution loop that reads the bytecode array. It utilizes a fast direct-threaded dispatch loop and a low-level stack array for all mathematical operations and variable storage.

## Features Supported

* **Data Types:** 32-bit Integers (Booleans evaluate as `1` for true, `0` for false).
* **Arithmetic:** Addition (`+`), Subtraction (`-`), Multiplication (`*`), Division (`/`).
* **Relational Operators:** Equality (`==`), Less Than (`<`).
* **Variables:** Assignment and reassignment using `let x = 10;`.
* **Control Flow:** Block statements (`{ }`), conditional execution (`if` / `else`), and loops (`while`).
* **I/O:** Interactive terminal inputs (`input`) and console outputs (`print`).
* **Debug Mode:** Built-in disassembler to view the generated raw bytecode array before execution.

## Build Instructions

To compile the CVM++ interpreter, use a modern C++ compiler (C++20 recommended to enable the latest performance hints):

```bash
g++ -O3 -std=c++20 cvm.cpp -o cvm
```

## Usage

Run a script by passing the filename as an argument:

```bash
./cvm <script_name>
```

**View the AST:**
To see the Abstract Syntax Tree generated by the parser, use the `--show-ast` flag:

```bash
./cvm --show-ast <script_name>
```

**View the Bytecode:**
To see the raw instruction array generated by the compiler before the VM executes it, use the debug flag:

```bash
./cvm --show-bytecode <script_name>
```

## Testing Scripts

Below are test scripts that verify different components of the CVM++ architecture. Save these as `.cvm` files and pass them to the interpreter.

### Benchmark & Stress Tests

**1. Comprehensive Benchmark (`stress_full.cvm`)**
A hardcore ALU and control-flow stress test. It evaluates all mathematical operations (`+`, `-`, `*`, `/`), comparisons (`==`, `<`), and branching (`while`, `if/else`) inside a 1,000,000 iteration hot loop. Used to calculate the throughput metric.

**2. Tight Loop Benchmark (`stress.cvm`)**
A minimalistic loop test designed to measure the raw baseline overhead of the dispatch loop and `JUMP` instructions.

### Safety Checks

**3. Division By Zero (`test_div_zero.cvm`)**
Verifies that the VM intercepts `x / 0` and throws a graceful runtime exception instead of crashing the OS process with a hardware fault.

**4. Undefined Variables (`test_undefined_var.cvm`)**
Verifies that the compiler prevents usage of uninitialized variables (e.g., printing a variable that was never defined via `let`).

### Architecture Tests

**5. Arithmetic & Precedence (`arith.cvm`)**
Verifies that the recursive descent parser correctly enforces the order of operations and handles parentheses.

**6. Interactive Inputs & Variable Memory (`area_rect.cvm`)**
Tests the `input` keyword, pausing the VM execution loop to wait for standard input, and maps the values to variables in the global memory array.

**7. Signed Integers & Identity (`negative.cvm`)**
Tricks the compiler into creating negative numbers by subtracting from zero, testing if the VM's integer stack correctly handles signed 32-bit drops below zero.

**8. Conditional Branching (`major_or_minor.cvm`)**
Tests the `OP_JUMP_IF_FALSE` and `OP_JUMP` instructions. The compiler must correctly calculate the offset to jump over the `else` block if the `if` condition evaluates to true.

**9. Loop Accumulator (`loop.cvm`)**
Tests backward jump patching to repeat the loop block and forward jump patching to exit the loop when the condition fails.
